# mei-allin 整合项目实现计划

## 定位
把 8 个异构开源 Web 应用，通过「**统一外壳 Shell + Nginx 网关 + 主题注入 + 插件化清单**」整合为一个 docker-compose 项目。**不动任何上游源码**，只做交互层"皮"的协调与统一，保留各应用完整功能；通过抽象设计支持局部升级与扩展更多应用。

## 锁定的设计决策（采用推荐默认）
- **视觉语言**：暗色玻璃拟态（底 `#0f1117` / 卡 `#1c1f2a+blur` / 主色靛蓝→紫渐变 `#6366f1→#7c3aed` / 圆角 16px）。tokens.css 同时定义亮色双色板，为后续自适应预留。
- **门户主页**：全部用自研 Shell 门户，8 个应用作为卡片网格展示。
- **拓扑**：子域名（`{app}.allin.local` 或 `{app}.<ip>.nip.io`），避免破坏 SPA base-path。
- **认证**：Shell 自管入口门禁 + 各应用保持自身登录（起步完全不动源码）。
- **网关**：Nginx + `sub_filter` 注入 theme loader，剥离 `X-Frame-Options`/`CSP`。
- **Shell 技术**：Next.js 14 App Router（与 LunaTV/tutorial 同栈，经验复用）。

## 四层抽象
| 层 | 职责 | 升级影响 |
|---|---|---|
| L1 网关 | 反代、剥头、注入 loader | nginx 配置片段 |
| L2 Shell | 门户、导航、主题源、iframe 宿主 | 自有代码，与 app 解耦 |
| L3 主题 | tokens.css + 每 app 协调 CSS | 改 token 全局，改 app.css 局部 |
| L4 插件清单 | 每 app 一个 manifest | 新增 app = 加清单+1 service |

## 插件清单 schema（核心扩展机制）
`plugins/<id>/manifest.yml` 字段：`id, name, icon(lucide/iconify), category, weight, endpoint(内部 docker 地址), ingress.{mode,host}, auth.strategy(independent), embed.{iframe,strip_headers}, theme.{has_skin,entry}, health.{path,expect}, upgrade.image`。
Shell 构建期扫描 `plugins/*/manifest.yml` 生成导航与 iframe 配置；新增第 9 个 app 只需加清单 + compose service + nginx server，**零 Shell 代码改动**。

## 主题注入机制（只做皮、跨异构框架的关键）
1. `tokens.css`：CSS 变量定义全局视觉（主色/字体/圆角/阴影/暗亮双色板）。
2. `loader.js`：被网关 `sub_filter` 注入到每个 app `<head>` 末尾，带 `data-app="<id>"`；在 iframe 内部运行 → 拉 `tokens.css`+`<app>.css` 注入 → 监听 `postMessage` 实时切主题。
3. `theme.css`（每 app）：针对该 app 真实 DOM 选择器写覆盖规则，引用 tokens 变量。
4. nginx 注入（零源码改动）：
   ```
   sub_filter '</head>' '<script src="https://__SHELL__/__theme/loader.js" data-app="__APP__"></script></head>';
   sub_filter_once on;
   proxy_hide_header X-Frame-Options;
   proxy_hide_header Content-Security-Policy;
   ```

## 分阶段实施
- **阶段 0 · 骨架**：`git init`；建目录；`.env.example`（ROOT_DOMAIN/密码/卷路径）；`scripts/setup-ip.sh`；`docker-compose.yml` 雏形（网关+Shell 占位+redis+kvrocks）；`README.md`（部署/扩展/升级三节）；manifest schema + JSON Schema 校验脚本。
- **阶段 1 · 主题系统**：`tokens.css`（暗色玻璃拟态 + 亮色备选）；`loader.js`（注入+postMessage 切换）；`scripts/build-theme.mjs`（聚合 `plugins/*/theme.css` → `public/__theme/<app>.css`）。
- **阶段 2 · Shell 门户**：Next.js 14 项目；登录页（环境变量门禁）；门户首页（读 manifests 渲染卡片网格，分组/搜索/最近使用）；iframe 宿主布局（顶栏+侧栏+iframe 主区）；主题控制台（亮/暗切换 + 主色调，postMessage 广播）；`/api/plugins` 返回聚合清单；`/api/health` 轮询各 app。
- **阶段 3 · 标杆打通**：先接 **tutorial**（同栈、已有 CSS vars）→ 验证 nginx 注入 + iframe + 协调 CSS 闭环；再接 **mei-link**（原生 JS，最易）。两个跑通即证明机制可行。
- **阶段 4 · 批量接入**：按难度从低到高接 ai-draw → mediago → lunatv(+kvrocks) → solara → sun-panel → omni-tools；每接入一个写对应 `theme.css` 并视觉冒烟。
- **阶段 5 · 网关完善**：`conf.d/<app>.conf` 模板化（占位变量替换）；`inject.conf` 统一注入片段；健康检查徽标；加载/错误态。
- **阶段 6 · 体验打磨**：全局搜索；最近使用（localStorage）；移动端适配（顶栏折叠、底部 tab）；PWA manifest。
- **阶段 7 · 可选增强（按需）**：mkcert 一键 HTTPS 脚本；为支持 token 的应用加自动登录适配；预留 sun-panel "经典启动器模式"开关。
- **阶段 8 · 文档**：部署指南、扩展指南（加第 9 个 app）、上游升级指南、主题定制指南、架构说明。

## 风险与对策
- **omni-tools（MUI/Emotion）主题统一最难**：MUI 用 inline 样式，CSS 覆盖力弱，仅做配色近似，必要时 `!important`，明确标注为"部分协调"。
- **协调 CSS 随上游 DOM 变化失效**：升级流程含"视觉冒烟"步骤；theme.css 集中在 `plugins/<id>/` 便于定位修复。
- **子域名 + HTTPS 内网门槛**：默认 HTTP，HTTPS 作为可选增强并配脚本；提供 nip.io 零配置方案。
- **跨子域 iframe 少数功能异常**（如用 `window.top` 的 app）：降级为"新窗口打开"，清单 `embed.iframe:false`。

## 首个里程碑（本次会话将完成）
完成阶段 0（骨架）+ 阶段 1（主题系统）+ 阶段 2（Shell 门户核心）+ 阶段 3（tutorial、mei-link 两个标杆打通），形成**可运行的最小闭环**：浏览器访问 `http://allin.local`（或 nip 域名）→ 看到门户 → 点进 tutorial/mei-link → 经 iframe 嵌入、主题已统一。其余应用在后续会话按阶段 4 批量接入。
